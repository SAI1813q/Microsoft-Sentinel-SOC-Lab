
# 🤖 Playbooks & Automation

## 📖 Overview

Microsoft Sentinel Playbooks and Automation Rules extend the capabilities of a traditional SIEM by introducing **Security Orchestration, Automation, and Response (SOAR)**. They automate repetitive incident response tasks, reduce manual effort, and ensure security events are handled consistently according to predefined workflows.

This project implements both **Microsoft Sentinel Automation Rules** and **Azure Logic Apps** to automate incident triage and analyst notification. Automation Rules are used to update incident properties, assign owners, and add contextual information, while Logic Apps provide external notifications and integrate Microsoft Sentinel with other services.

Each automation documented below includes its purpose, configuration, execution workflow, validation, and supporting screenshots.

# ⚙️ User Added to Local Administrators

## 📖 Overview

This Microsoft Defender **Enhanced Automation Rule** automatically triages high-priority privilege escalation alerts generated by Microsoft Sentinel. When the **User Added to Local Administrators** analytics rule creates an alert, this automation immediately updates the alert status and assigns it to the designated Tier 3 SOC analyst for investigation.

By eliminating manual alert assignment, the automation ensures that privilege escalation incidents are acknowledged, prioritized, and routed to the appropriate analyst as soon as they are detected.

---

## 🎯 Purpose

This automation was implemented to streamline the initial triage of privilege escalation incidents and improve the efficiency of the Security Operations Center (SOC).

Its primary objectives are:

- Automatically identify high-priority privilege escalation alerts.
- Immediately update the alert status to **In Progress**.
- Automatically assign the alert to the designated Tier 3 SOC analyst.
- Reduce manual triage effort and ensure consistent incident handling.

---

## ⚡ Trigger

The automation is configured to execute whenever a **new alert is created** within Microsoft Defender. It continuously monitors newly generated alerts and evaluates whether they match the configured analytics rule.

| Setting | Value |
|---------|-------|
| Trigger Event | When a new alert is created |
| Alert Source | Microsoft Sentinel Analytics Rule |
| Target Alert | **User Added to Local Administrators** |
| Execution Scope | All current and future Microsoft Sentinel workspaces |

---

## 🔍 Conditions

Before executing any automated action, the rule evaluates the following condition:

| Condition | Value |
|-----------|-------|
| Analytic Rule Name | **User Added to Local Administrators** |

If the alert matches the configured analytics rule, the automation proceeds to execute the predefined actions.

---

## ⚙️ Automated Actions

When all conditions are satisfied, the automation performs the following actions automatically:

| Action | Value |
|---------|-------|
| Update Alert Status | **In Progress** |
| Assign Alert | Designated Tier 3 SOC Analyst |
| Rule Expiration | Indefinite |

---

## 🔄 Automation Workflow

```text
User Added to Privileged Group
            │
            ▼
Windows Security Event Generated
(Event ID 4728)
            │
            ▼
Microsoft Sentinel Analytics Rule Triggered
            │
            ▼
Alert Created
            │
            ▼
Enhanced Automation Rule Evaluates Alert
            │
            ▼
Alert Matches "User Added to Local Administrators"
            │
            ▼
Alert Status Updated → In Progress
            │
            ▼
Alert Assigned to Tier 3 SOC Analyst
```

---

## ✅ Validation

The automation was successfully validated by generating a **User Added to Local Administrators** alert within the lab environment.

The following observations confirmed successful execution:

- The Enhanced Automation Rule executed immediately after the alert was created.
- The automation correctly identified the **User Added to Local Administrators** analytics rule.
- The alert status was automatically updated to **In Progress**.
- The alert was successfully assigned to the designated Tier 3 SOC analyst.
- No manual analyst interaction was required during the triage process.

This successful validation confirms that the automation functions as expected and consistently performs the configured incident triage actions.

---

## 📈 Automation Benefits

This automation provides several operational benefits:

- Eliminates manual alert assignment.
- Standardizes privilege escalation incident triage.
- Reduces analyst response time.
- Ensures critical alerts are immediately acknowledged.
- Demonstrates Microsoft Sentinel SOAR capabilities using Enhanced Automation Rules.

# ⚙️ Add Triage Tag

## 📖 Overview

This Microsoft Defender **Standard Automation Rule** automatically applies the **Triage Required** tag to incidents generated by selected Microsoft Sentinel correlation analytics rules within the **LAW-Project1** workspace.

The automation ensures that incidents produced by high-fidelity correlation detections are immediately identified for analyst review, allowing the Security Operations Center (SOC) to prioritize investigation and maintain a consistent triage process.

---

## 🎯 Purpose

This automation was implemented to improve incident visibility and streamline the SOC triage process.

Its primary objectives are:

- Automatically identify incidents generated by the configured correlation analytics rules.
- Apply the **Triage Required** tag to highlight incidents requiring analyst attention.
- Standardize the initial triage workflow across correlation-based detections.
- Reduce manual effort by automatically categorizing incidents.

---

## ⚡ Trigger

The automation is configured to execute whenever a **new incident is created** within the **LAW-Project1** Microsoft Sentinel workspace.

It evaluates every newly created incident and proceeds only if the incident originates from one of the configured correlation analytics rules.

| Setting | Value |
|---------|-------|
| Trigger Event | When a new incident is created |
| Incident Source | Microsoft Sentinel Analytics Rules |
| Workspace | LAW-Project1 |

---

## 🔍 Conditions

Before executing any automated action, the automation evaluates the following condition:

| Condition | Value |
|-----------|-------|
| Group Operator | AND |
| Analytic Rule Name | Contains any of the configured correlation analytics rules |

### Configured Analytics Rules

- `correaltion 1`
- `correlation 2`
- `correaltion 3`
- `correation 4`
- `correlation 5`
- `correaltion 6`

If the incident is generated by any of the above analytics rules, the automation proceeds to execute the configured action.

> **Note:** The rule names above match the names configured within the lab environment.

---

## ⚙️ Automated Actions

When the specified conditions are satisfied, the automation automatically performs the following action:

| Action | Value |
|---------|-------|
| Add Tag | **Triage Required** |
| Rule Execution Order | 5 |
| Rule Expiration | Indefinite |

---

## 🔄 Automation Workflow

```text
Correlation Analytics Rule Triggered
(Correlation 1 – Correlation 6)
            │
            ▼
Microsoft Sentinel Incident Created
            │
            ▼
Standard Automation Rule Evaluates Incident
            │
            ▼
Incident Matches Configured Analytics Rule
            │
            ▼
"Triage Required" Tag Applied
            │
            ▼
SOC Analyst Prioritizes Incident for Investigation
```

---

## ✅ Validation

The automation was successfully validated by generating an incident from one of the configured correlation analytics rules.

The following observations confirmed successful execution:

- The Standard Automation Rule executed immediately after the incident was created.
- The automation correctly identified the incident as originating from one of the configured correlation analytics rules.
- The **Triage Required** tag was automatically applied to the incident.
- The incident was immediately categorized for analyst review without requiring manual interaction.

This successful validation confirms that the automation consistently tags correlation-based incidents, enabling analysts to quickly identify and prioritize investigations.

---

## 📈 Automation Benefits

This automation provides several operational benefits:

- Improves visibility of high-fidelity correlation incidents.
- Standardizes the incident triage process.
- Reduces manual tagging effort.
- Enables faster prioritization by SOC analysts.
- Demonstrates Microsoft Sentinel SOAR capabilities using Standard Automation Rules.
